# Claude Widget App - Development Notes

## Overview
These notes document the major technical hurdles, edge cases, and solutions discovered while building the Claude API Usage Widget for Android. The app consists of a main Activity (for WebView authentication and settings) and a background WorkManager + AppWidgetProvider to periodically fetch and display API usage data on the home screen.

## 1. Bypassing Cloudflare Bot Protection (403 Forbidden)
Claude's API endpoints (`/api/organizations` and `/api/organizations/{orgId}/usage`) are heavily protected by Cloudflare. 
* **The Problem:** Making standard background API requests via `OkHttp` instantly returned 403 Forbidden, because Cloudflare detects the default OkHttp TLS fingerprint and missing browser headers.
* **The Solution:** 
  * We passed the exact `User-Agent` string generated by the user's authenticating `WebView` directly to the `OkHttp` client.
  * We extracted the `Cookie` string from `CookieManager` (which includes the crucial `cf_clearance` clearance cookie and `sessionKey` auth token) and attached it to the OkHttp requests.
  * Added mandatory browser-like headers: `Accept: application/json` and `Referer: https://claude.ai/`.

## 2. Google OAuth & WebView Security
* **The Problem:** When logging in via Google OAuth, Google blocks standard Android WebViews with a "Browser not secure" error. Furthermore, after logging in, the Next.js/React SPA would crash and show a blank white screen.
* **The Solution:**
  * **OAuth Bypass:** Stripped the `"; wv"` substring from the `WebView`'s `User-Agent`. This simple trick causes Google to treat the WebView like a standard mobile Chrome browser, allowing the OAuth flow.
  * **SPA Crash Fix:** Modern auth flows require robust browser features. We explicitly enabled:
    * `setAcceptThirdPartyCookies(webView, true)`
    * `domStorageEnabled = true` (localStorage)
    * `databaseEnabled = true` (IndexedDB)
    * `javaScriptEnabled = true`
    * Added a `WebChromeClient()`

## 3. The "White Screen" Premature Login Bug
* **The Problem:** The app initially tried to detect a successful login by checking if the URL contained `/login` or `auth` and whether a `sessionKey` cookie existed. However, users often had an old/expired `sessionKey` from a previous session. Because Claude's auth flow rapidly redirects through URLs containing `auth`, the app would prematurely hide the WebView and declare "Success" before the user actually logged in. The subsequent API calls would then fail.
* **The Solution:** 
  * Completely overhauled `MainActivity.kt`. We stopped relying on fragile URL string matching.
  * Instead, on `onPageFinished`, we fetch all cookies for `https://claude.ai`. 
  * If a valid `sessionKey=` exists (and isn't `sessionKey=deleted`), we save it and trigger the success screen. The user naturally reaches this state once Claude accepts their credentials and redirects them to the authenticated dashboard.

## 4. Background Workers & Instant Widget Refreshes
* **The Problem:** The widget showed default dummy data (98% / 100%) and tapping the "Refresh" icon did nothing.
* **The Solution:** 
  * `PeriodicWorkRequest` enforces a minimum 15-minute delay and cannot run instantly.
  * Created a dedicated `runNow()` method using `OneTimeWorkRequestBuilder` that executes immediately.
  * The widget's Refresh button BroadcastReceiver now triggers `runNow()` while instantly updating the widget text to "Refreshing...".
  * The periodic worker was updated to use `ExistingPeriodicWorkPolicy.UPDATE` / `CANCEL_AND_REENQUEUE`, allowing dynamic intervals (15m, 30m, 1h, 2h, 4h) configurable via a new Settings UI in the main app.
  * Added a "Never (manual only)" option (interval `0L`) that explicitly cancels the periodic `WorkManager` job.

## 5. Android Widget (RemoteViews) UI Constraints
* **The Problem:** The widget crashed with an "error occurred when loading widget" message, and later the layout was too large and getting cut off at the 2x2 size.
* **The Solution:**
  * **Crash Fix:** Android's `RemoteViews` does NOT support complex theme attributes like `?android:selectableItemBackgroundBorderless`. Removing this attribute fixed the fatal crash.
  * **Responsive Layouts:** Android widgets don't support modern responsive layout systems (like ConstraintLayout wrapping perfectly). We created two separate layouts:
    1. `widget_layout.xml`: A vertically stacked, extremely compact layout (11sp text, 6dp progress bars, tight padding, `gravity="center_vertical"`) optimized to fit in a 2x2 grid without getting cut off.
    2. `widget_layout_wide.xml`: A side-by-side horizontal layout optimized for 3x1 and 4x1 heights.
  * Implemented `onAppWidgetOptionsChanged` in `ClaudeWidgetProvider` to dynamically switch between these layouts based on the widget's current pixel height.

## 6. Minor UI Fixes
* **Spinner Visibility:** The interval settings dropdown used dark text on a dark background. Fixed by creating custom `spinner_item.xml` and `spinner_dropdown_item.xml` with `#FFFFFF` text and transparent backgrounds.
* **Text Truncation:** Ensured all widget `TextView`s use `maxLines="1"` to prevent vertical expansion and layout breakage in tightly constrained widget spaces.
