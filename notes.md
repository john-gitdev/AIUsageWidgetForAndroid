# AI Usage Widget App - Development Notes

## Overview
These notes document the major technical hurdles, edge cases, and solutions discovered while building the AI Usage Widget for Android. The app consists of a main Activity (for WebView authentication and settings) and a background WorkManager + AppWidgetProvider to periodically fetch and display API usage data on the home screen.

## 1. Bypassing Cloudflare Bot Protection (403 Forbidden)
Claude's API endpoints (`/api/organizations` and `/api/organizations/{orgId}/usage`) are heavily protected by Cloudflare. 
* **The Problem:** Making standard background API requests via `OkHttp` instantly returned 403 Forbidden, because Cloudflare detects the default OkHttp TLS fingerprint and missing browser headers.
* **The Solution:** 
  * We passed the exact `User-Agent` string generated by the user's authenticating `WebView` directly to the `OkHttp` client.
  * We extracted the `Cookie` string from `CookieManager` (which includes the crucial `cf_clearance` clearance cookie and `sessionKey` auth token) and attached it to the OkHttp requests.
  * Added mandatory browser-like headers: `Accept: application/json` and `Referer: https://claude.ai/`.

## 2. Google OAuth & WebView Security
* **The Problem:** When logging in via Google OAuth, Google blocks standard Android WebViews with a "Browser not secure" error. Furthermore, after logging in, the Next.js/React SPA would crash and show a blank white screen.
* **The Solution:**
  * **OAuth Bypass:** Stripped the `"; wv"` substring from the `WebView`'s `User-Agent`. This simple trick causes Google to treat the WebView like a standard mobile Chrome browser, allowing the OAuth flow.
  * **SPA Crash Fix:** Modern auth flows require robust browser features. We explicitly enabled:
    * `setAcceptThirdPartyCookies(webView, true)`
    * `domStorageEnabled = true` (localStorage)
    * `databaseEnabled = true` (IndexedDB)
    * `javaScriptEnabled = true`
    * Added a `WebChromeClient()`

## 3. The "White Screen" Premature Login Bug
* **The Problem:** The app initially tried to detect a successful login by checking if the URL contained `/login` or `auth` and whether a `sessionKey` cookie existed. However, users often had an old/expired `sessionKey` from a previous session. Because Claude's auth flow rapidly redirects through URLs containing `auth`, the app would prematurely hide the WebView and declare "Success" before the user actually logged in. The subsequent API calls would then fail.
* **The Solution:** 
  * Completely overhauled `MainActivity.kt`. We stopped relying on fragile URL string matching.
  * Instead, on `onPageFinished`, we fetch all cookies for `https://claude.ai`. 
  * If a valid `sessionKey=` exists (and isn't `sessionKey=deleted`), we save it and trigger the success screen. The user naturally reaches this state once Claude accepts their credentials and redirects them to the authenticated dashboard.

## 4. Background Workers & Instant Widget Refreshes
* **The Problem:** The widget showed default dummy data (98% / 100%) and tapping the "Refresh" icon did nothing.
* **The Solution:** 
  * `PeriodicWorkRequest` enforces a minimum 15-minute delay and cannot run instantly.
  * Created a dedicated `runNow()` method using `OneTimeWorkRequestBuilder` that executes immediately.
  * The widget's Refresh button BroadcastReceiver now triggers `runNow()` while instantly updating the widget text to "Refreshing...".
  * The periodic worker was updated to use `ExistingPeriodicWorkPolicy.UPDATE` / `CANCEL_AND_REENQUEUE`, allowing dynamic intervals (15m, 30m, 1h, 2h, 4h) configurable via a new Settings UI in the main app.
  * Added a "Never (manual only)" option (interval `0L`) that explicitly cancels the periodic `WorkManager` job.

## 5. Android Widget (RemoteViews) UI Constraints
* **The Problem:** The widget crashed with an "error occurred when loading widget" message, and later the layout was too large and getting cut off at the 2x2 size.
* **The Solution:**
  * **Crash Fix:** Android's `RemoteViews` does NOT support complex theme attributes like `?android:selectableItemBackgroundBorderless`. Removing this attribute fixed the fatal crash.
  * **Responsive Layouts:** Android widgets don't support modern responsive layout systems (like ConstraintLayout wrapping perfectly). We created two separate layouts:
    1. `widget_layout.xml`: A vertically stacked, extremely compact layout (11sp text, 6dp progress bars, tight padding, `gravity="center_vertical"`) optimized to fit in a 2x2 grid without getting cut off.
    2. `widget_layout_wide.xml`: A side-by-side horizontal layout optimized for 3x1 and 4x1 heights.
  * Implemented `onAppWidgetOptionsChanged` in `ClaudeWidgetProvider` to dynamically switch between these layouts based on the widget's current pixel height.

## 6. Minor UI Fixes
* **Spinner Visibility:** The interval settings dropdown used dark text on a dark background. Fixed by creating custom `spinner_item.xml` and `spinner_dropdown_item.xml` with `#FFFFFF` text and transparent backgrounds.
* **Text Truncation:** Ensured all widget `TextView`s use `maxLines="1"` to prevent vertical expansion and layout breakage in tightly constrained widget spaces.

## 7. Caching Google OAuth Session on Re-login
* **The Problem:** Clicking "Re-login to Claude" called `CookieManager.getInstance().removeAllCookies(null)`, wiping all cookies across every domain. This forced the user to re-enter their Google email, password, and 2FA credentials from scratch every single time.
* **The Solution:**
  * Replaced global `removeAllCookies()` with domain-specific clearing (`clearClaudeSession()`) targeting `claude.ai` and `anthropic.com` cookies and WebStorage origins.
  * Preserved Google session cookies (`accounts.google.com`, `google.com`) so Google's 1-tap account picker appears immediately when selecting "Continue with Google".
  * Enabled third-party cookies on popup WebViews (`setAcceptThirdPartyCookies`) and called `CookieManager.getInstance().flush()` to ensure sessions persist across activity lifecycles.
  * Added a dedicated "Log out completely" option for cases where the user explicitly wants to purge all accounts including Google.

## 8. Multi-Widget Support: ChatGPT / Codex Integration
* **Implementation:**
  * Added dedicated `ChatGptWidgetProvider`, `chatgpt_widget_layout.xml` (compact 2x2) and `chatgpt_widget_layout_wide.xml` (wide 4x2) featuring official ChatGPT branding and styling.
  * Endpoints: Fetches usage from `https://chatgpt.com/backend-api/wham/usage` with automatic token refresh via `https://chatgpt.com/api/auth/session`.
  * Rate limit parsing: Tracks `rate_limit.primary_window` (session limit) and `rate_limit.secondary_window` (weekly limit) with epoch reset countdown calculations.
  * Tabbed In-App UI: `MainActivity` provides a seamless tab switcher between Claude and ChatGPT with independent authentication flows and Google OAuth session reuse.


## 9. Separate Login Browsers, Widget Tab Routing & In-App Log
* **Shared WebView bug:** Both tabs used one `WebView`, one popup and one login poller that checked `currentTab`. A Claude page still running (for example, a post-login redirect) could take over the ChatGPT tab, and each tab's login state leaked into the other.
  * Each service now has its own `LoginBrowser` (WebView, Google sign-in popup, login poller), tied to that service instead of the current tab. Switching tabs only changes which one is visible, so a half-finished login is still there when you come back. Once a login is detected, that browser loads `about:blank` so the site's scripts stop running in the background.
  * Cookies are still shared app-wide per domain (that's what lets the Google sign-in carry over), so the two browsers only share Google.
* **Re-login didn't clear ChatGPT's session:** Deleting a `__Secure-` or `__Host-` cookie (like `__Secure-next-auth.session-token`) needs the `Secure` attribute. Without it the browser silently ignores the deletion, so the old session survived. The expiry strings now include `Secure`.
* **"Log out completely" only affects the current service** (plus all cookies, to reliably clear Google). The other service stays logged in, because its widget and tab use the session saved in prefs.
* **Widget opened the wrong tab:** The Claude widget never said which tab to open. And because the intent was a plain launcher intent, an already-running app just came to the front without seeing it. Widgets now use `MainActivity.openTabIntent()` (`NEW_TASK | CLEAR_TOP | SINGLE_TOP` plus the tab), which reaches `onNewIntent` when the app is open. If the last refresh failed, the tab says so (for example, "Claude Session Expired") instead of "Connected!".
* **In-app log (`AppLog`):** Logcat needs a computer, so refresh results, HTTP errors (status plus the start of the error body, which shows things like a Cloudflare challenge page), and login events are appended to `files/app_log.txt` (capped at 128 KB). The **Log** button in the tab bar shows it newest first, with Copy and Clear. Cookies, tokens and bodies of successful responses are never logged.

## 10. Refreshes Failing on Network Handovers
* **The problem:** Moving from Wi-Fi to mobile data (and some overnight runs) logged `UnknownHostException: Unable to resolve host "claude.ai": No address associated with hostname` for both services, and the widgets switched to "Error" until the next refresh 15+ minutes later. DNS failing like this means the app had no usable connection at that moment: the handover gap, or the system blocking the app's network while it was in the background. Neither `runNow()` nor the periodic request had a network constraint, so WorkManager ran them anyway.
* **The solution:**
  * All work requests require `NetworkType.CONNECTED`. JobScheduler then runs them only on a validated network that the app is allowed to use, so a tap made offline waits and runs once the connection is back.
  * An `IOException` counts as "offline" rather than an error. The worker returns `Result.retry()` (exponential backoff from 15 s) for up to 4 attempts, keeps the last readings, and sets the status line to `Offline · <time of last good reading>` (from the new `updated_at` / `chatgpt_updated_at` prefs). "Error" is only shown when there's no reading to keep.
  * Tap-to-refresh uses unique work (`ClaudeWidgetRefreshNow`, `REPLACE`), so taps made while waiting don't pile up retrying runs. The tap checks `hasUsableNetwork()` and shows "Waiting for network..." instead of a "Refreshing..." that can't finish.
  * Periodic work used to be registered only on login or an interval change, so existing installs kept the old request. `MainActivity.onCreate` now calls `schedulePeriodic()` (policy `UPDATE`, which keeps the schedule's timing) whenever a service is logged in.
  * `refreshChatGptToken()` lets `IOException` through. Before, a dropped connection there looked like a logged-out session.
